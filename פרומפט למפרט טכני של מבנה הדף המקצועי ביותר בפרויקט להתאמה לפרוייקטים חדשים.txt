# 📋 מפרט טכני — דף "מרכז ניהול" (Admin Hub) — הדף המקצועי ביותר בפרויקט

מסמך זה מתאר את **מבנה הדף המקצועי ביותר** בפרויקט — מרכז ניהול עם 9 מודולים בגריד + מודאל לכל מודול. אין כאן שמות קבצים או נתיבים — רק ארכיטקטורה, קומפוננטות, חוזי-נתונים ומצבים, שמאפשרים לשחזר את הדף בפרויקט אחר.

---

## 1. תקציר — מהות הדף ולמה הוא "מקצועי"

| מאפיין | תיאור |
|---|---|
| **סוג** | Single-Page Control Center — כל הניהול בדף אחד, בלי ניווט בין מסכים |
| **מודל** | Hub-and-Spoke: גריד כרטיסים = Hub, מודאל לכל מודול = Spoke |
| **כניסה** | מוגן ב-Admin Gate (רק uid מורשה רואה את הדף) |
| **מהירות** | כל מודול נטען לוקאלית מ-cache (60s TTL), תגובה ~0.01s |
| **פריסה** | 9 מודולים בגריד אוטומטי + KPI עליון + מודאל מפורט לכל מודול |
| **עיקרון מרכזי** | "3 שכבות מידע": KPI → רשימה → פעולה. בכל מודול. |

---

## 2. עקרונות מנחים

1. **כל מודול = כרטיס אחד = 1 KPI + 1 תצוגה מקדימה + 1 כפתור פעולה.**
2. **אפס ניווט בין מודולים** — לחיצה פותחת מודאל, לא מסך חדש.
3. **טעינה עצלה** — נתוני כל מודול נטענים רק בפתיחה הראשונה שלו (lazy), ואז נשמרים בזיכרון.
4. **KPI עליון אגרגטיבי** — 3–4 מדדים שמסכמים את כל המודולים, גלויים מיד בכניסה.
5. **אין מודול "ריק"** — אם אין נתונים, מציגים Empty State עם כפתור פעולה ראשי (לא מסך לבן).
6. **כל פעולה משנה = דורשת אישור (confirm)** לפני שהיא נשלחת ל-API.
7. **כל פעולה נרשמת ב-audit log** עם uid, זמן, ומה השתנה.

```json
  "items": [
    { "id": "...", "primary": "...", "secondary": "...", "meta": {...}, "actions": [...] }

    { "id": "approve_user", "label": "אשר משתמש", "primary": true }
  ],
  "empty_state": { "icon": "📭", "text": "אין נתונים" },
  "last_updated": "2026-11-18T10:00:00Z"
}
```

## 8. מצבי המודול (States)

| מצב | חזות | התנהגות |
|---|---|---|
| **Loading (initial)** | skeleton על KPI + 3 שורות skeleton | אין כפתורי פעולה |
| **Empty** | אייקון 48px + טקסט + כפתור Primary | הכפתור פותח את פעולת היצירה |
| **Error** | גבול אדום + ⚠️ + "נסה שוב" | כפתור Retry |
| **Partial** | רוב השורות נטענו, 1–2 עם סימן ⏳ | polling כל 5s עד שהכל נטען |
| **Success** | רשימה מלאה + KPI | — |
| **Unauthorized** | 🔒 + "אין הרשאה" | אין כפתור — סגור אוטומטית |
| **Stale** | באנר עליון "הנתונים מלפני 5 דק׳" + כפתור רענון | רענון ידני |

## 9. אינטראקציות

### 9.1 זרימת פתיחת מודול
```
Tap על כרטיס
  → אנימציית scale(0.98) 120ms
  → Modal opens: fade + translateY(12px)→0, 200ms
  → Fetch נתונים (אם לא ב-cache)
  → הצגת skeleton אם טעינה >200ms
  → רינדור סופי
```

### 9.2 זרימת פעולה (action)
```
Tap על כפתור פעולה (למשל "אשר משתמש")
  → Dialog אישור (confirm) עם שם המשתמש וה-action
  → Tap "אשר" → כפתור הופך ל-loading (spinner פנימי)
  → API call
  → הצלחה: toast ירוק + רענון הרשימה + רענון KPI של המודול + רענון KPI עליון
  → כשל: toast אדום + הכפתור חוזר למצב רגיל + הכפתור לא "נעלם"
```

### 9.3 זרימת סגירה
```
Tap ✕ / ← חזרה / Escape / overlay
  → Modal closes: fade + translateY(0)→12px, 180ms
  → Focus חוזר לכרטיס שפתח
```

### 9.4 רענון גלובלי
- כפתור Refresh בסקשן העליון.
- טוען את 9 ה-KPIs במקביל (`Promise.all`).
- מציג "מרענן..." קטן ליד הכותרת.
- לא מפנה למסך חדש — רק מעדכן במקום.

### 9.5 פילטור/סינון בתוך מודאל
- אם יש >10 שורות — מוסיפים שורת chips לסינון ("הכל / מאושרים / ממתינים").
- Chips: pill, 32px, רקע accent שקוף לפעיל.
- סינון מקומי בצד הלקוח (לא API).

## 11. RTL — חוקים ספציפיים לדף זה

1. גריד: `grid-template-columns` עובד אוטומטית ב-RTL.
2. חץ בכרטיס מודול: **←** (שמאלה = "פתח").
3. חץ חזרה במודאל: **→** (ימינה = "חזור").
4. אייקונים סמנטיים (📊, 🔔) לא מתהפכים.
5. Padding של כרטיס: `padding-inline-start: 12px; padding-inline-end: 12px`.
6. Footer: כפתור Ghost ב**ימין**, Primary ב**שמאל** (הפוך מ-LTR).
7. KPI Grid: ימין→שמאל, שורה ראשונה = KPI ראשי.
8. Tab Bar מתחת — RTL, גלילה אופקית עם mask gradient.

## 12. ביצועים — חוקים קריטיים

| חוק | הסבר |
|---|---|
| **Cache 60s TTL** | כל מודול נשמר בזיכרון ל-60s. אין קריאה חוזרת לפני זה. |
| **Lazy per module** | נתוני מודול נטענים רק בפתיחה הראשונה שלו. |
| **Parallel KPI fetch** | 9 ה-KPIs העליונים נטענים במקביל בכניסה לדף. |
| **Optimistic UI** | פעולה משנה UI מיד, ומגלגלת חזרה אם ה-API נכשל. |
| **Skeleton > Spinner** | ספינר רק לפעולות משנה. |
| **No full reload** | רענון = עדכון במקום, לא `location.reload()`. |
| **Cache-bust** | אחרי כל שינוי JS/CSS — `?v=timestamp` כדי לעקוף cache דפדפן. |

## 13. אבטחה ושמירות

| שכבה | מנגנון |

## 14. טבלת KPI עליונה — מקורות נתונים

| KPI | מקור | חישוב |
|---|---|---|
| 👥 **משתמשים** | users table | `COUNT(*)` |
| 💰 **TVL** | קרנות מאושרות | `SUM(total_raised)` על status=approved |
| 🏊 **קרנות פעילות** | קרנות | `COUNT(*)` על status=open |
| 🔔 **התראות** | alerts table | `COUNT(*)` על read=false |

- כל KPI מתעדכן אחרי כל פעולה רלוונטית.
- אם אחד נכשל — מציג `—` וממשיך הלאה (לא שובר את כל הדף).

## 16. דפוס חזותי — "מרכז ניהול" בפרויקט אחר

אם אתה בונה פרויקט אחר ורוצה **אותו דף בדיוק**, השתמש במתכון הזה:

1. **בחר 6–12 "מודולים"** — ישויות שהאדמין צריך לנהל (משתמשים, תוכן, תשלומים, לוגים, הגדרות...).
2. **לכל מודול** — הגדר: אייקון, KPI ראשי, KPI משני, 1–3 פעולות, רשימה של פריטים.
3. **בנה KPI עליון** — 3–4 מדדים אגרגטיביים שמסכמים את כל המערכת.
4. **בנה גריד** — כל כרטיס = מודול. auto-fill.
5. **בנה מודאל אחד** — עם אותו anatomy (Header / KPI Grid / List / Footer), רק תוכן משתנה.
6. **חבר את כולם לאותו מנוע רינדור** — `renderModule(module_id, data)` יחיד.
7. **הוסף cache + lazy + optimistic UI** — כדי שהדף ירגיש כמו fintech אמיתי.
8. **הוסף audit + confirm** — כדי שכל פעולה תהיה בטוחה.

---

המסמך הזה **ניטרלי לחלוטין** — אין בו שמות קבצים, נתיבים או תלות בקוד המקורי. אפשר להדביק אותו כמו שהוא כ"בריף ארכיטקטוני" ל-Grok, והוא אמור לייצר דף ניהול זהה לחלוטין בשפה העיצובית ובארכיטקטורה.

רוצה שאוסיף **נספח עם דוגמת קוד** של `renderModule()` (פונקציית רינדור גנרית אחת שמטפלת בכל 9 המודולים) + דוגמת מבנה HTML של מודאל — כדי ש-Grok יתחיל מאותה נקודה?
